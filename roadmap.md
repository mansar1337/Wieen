# Wieen — дорожная карта

Документ отвечает на три вопроса: что уже работает, что мешает и в каком
порядке это чинить. Факты ниже проверены на живом клиенте; адреса и
наблюдения помечены как «проверено» или «гипотеза».

Дата: 2026-11-14. Ветка: `master`.

---

## 1. Статус

| слой | состояние |
|---|---|
| инъекция агента в клиент | **готово** — `ld.so.preload` рантайма flatpak (`tools/install_preload.sh`) |
| поиск образа клиента и функций Luau | **готово** — по хэшу образа и по сигнатурам (`src/agent/luau_symbols.h`) |
| поиск состояния Luau (`global_State`) | **готово** — скан резидентных страниц по якорю `cb.userthread` |
| хук без изменения кода клиента | **готово** — обработчик в слоте `cb.preresume` состояния VM |
| выбор VM игры из двух VM клиента | **готово** — проба `typeof(game) .. "/" .. typeof(workspace)` (`tools/probe.luau`) |
| права потока | **частично** — маска прав копируется у потока игры; контекста скрипта нет |
| выполнение скриптов | **готово** — исходник компилируется на хосте, байткод грузится клиентом |
| скрипты больше 279 байт байткода | **готово** — режутся на части, состояние между частями общее |
| `loadstring` | **готово** — свой: исходник компилирует хост, агент грузит и возвращает функцию |

### Что работает прямо сейчас

```sh
python3 src/cli/wieen.py exec 'return typeof(game)'            # Instance
python3 src/cli/wieen.py exec 'return tostring(workspace.CurrentCamera.CFrame)'
python3 src/cli/wieen.py exec 'local f = loadstring("return 6*7") return f()'   # 42
python3 tools/selftest.py                                     # 35/35
python3 tools/soak.py 60                                      # 6/6, клиент жив
```

### Ограничения

| ограничение | причина |
|---|---|
| `GetService` (кроме `Workspace`) возвращает `nil` | у потока агента нет контекста скрипта игры |
| `Instance.new` — «lacking capability CreateInstances» | та же причина |
| `print` не появляется в консоли F9 внутри игры | консоль берёт сообщения контекста скрипта |
| штатный `loadstring` клиента всегда отказывает | та же причина (движок Roblox) |
| байткод ≥ 280 байт не грузится | Roblox-обёртка `luau_load` берёт только такой байткод |

Все четыре ограничения — **одна причина**: контекст скрипта игры.

## 2. Три рубежа

### Рубеж 1. Исполнять код в потоке игры (рекомендуется)

Идея: выполнять наш скрипт **в том потоке, который вызывает `lua_resume`**.
Это поток скрипта игры, у него есть контекст целиком: все службы,
`Instance.new`, штатный `loadstring` клиента и консоль F9.

Не хватает одной вещи: функции вызова Luau из C (`lua_call` / `lua_pcall`)
**той же копии Luau**, что и у игры. Тогда:

1. агент грузит наш чанк в поток игры;
2. вызывает его через найденную функцию;
3. скрипт исполняется с контекстом игры.

Плюсы: код клиента не трогаем (переживает новые сборки), снимается сразу
четыре ограничения из таблицы выше. Минусы: нужна реверс-работа (поиск
функции) и аккуратная работа со стеком чужого потока.

### Рубеж 2. Уровень движка Roblox (C++)

Вызвать API движка так, чтобы он сам создал настоящий `LocalScript` с нашим
`Source`: движок выполнит его с полным контекстом. Требуется адрес API в
движке Roblox.

### Рубеж 3. Патч кода клиента + починка проверки целостности

Снимает все ограничения разом (и `loadstring`, и песочницу, и лимит 280
байт, и консоль), но клиент сверяет байты своего text и уходит примерно
через 65 секунд после старта. Значит, нужно найти эту проверку и подправить
ожидаемое значение. Хрупко: новая сборка клиента всё ломает.

**Рекомендация:** рубеж 1. Он единственный сохраняет главное свойство
проекта — инъекция в данные, без изменения кода клиента.

### Раскладка состояния Luau в клиенте

```
lua_State:  0x03 status   0x06 active   0x08 nCcalls   0x0a basecalls
            0x0c маска прав   0x30 ci   0x38 global   0x40 stack
            0x48 top   0x50 base

global_State: cb.userthread +0x6a0   cb.preresume +0x678
              cb.postresume +0x650   счётчик +0x6b0
```

Права потока лежат маской в `+0x0c`; у потока игры она `0x1`, у потока
агента без копии — `0`. Копия маски родителя даёт доступ к `game`,
`workspace` и `workspace.CurrentCamera`.

## 4. Ближайшие задачи

### A. Найти функцию вызова Luau (рубеж 1) — главное

Фильтр уже сузил круг: функция вызова из `lapi.cpp` обязана звать
`luaD_pcall` из группы `ldo.cpp` — той же, что `lua_resume` (`0x22e9432`).
Из 31 функции в диапазоне `0x22e6000..0x22e9400` фильтр оставил четыре:
`0x22e836e`, `0x22e8456`, `0x22e854e`, `0x22e8696`.

Что проверить:
- конвенция вызова: у Roblox `luau_compile` исходник — третий аргумент,
  возможно и у вызова другая;
- состояние потока в момент `preresume`: поток ещё `LUA_YIELD`, возможно
  вызов требует другого состояния;
- пробовать `lua_call` (три аргумента) вместо `lua_pcall` (четыре).

Способ проверки: агент с `WIEEN_ALTPCALL=<смещение>` и `WIEEN_INTHREAD=1`
вызывает кандидата на потоке игры и печатает результат; клиент при
неверном кандидате падает — поэтому перебор идёт с перезапуском клиента.

### B. Найти «чистый» загрузчик байткода (снять лимит 280 байт)

Roblox-обёртка `luau_load` (`0x22e4b72`) ограничивает размер; внутри
клиента есть и обычный загрузчик Luau — он где-то рядом с обёрткой
(группа `lvmload.cpp`). Найти его — и лимит 280 байт отпадает, а вместе с
ним исчезает необходимость резать скрипты на части.

### C. Разобрать конвенцию вызова компилятора клиента (`0x26d6400`)

Тогда `loadstring` работает без хоста, байткод сразу в формате клиента (без
нашего перевода опкодов — заодно снимается риск расхождения карты опкодов
на новых сборках).

### D. Перевод таблиц под новую сборку

Клиент иногда приходит новой сборкой (наблюдался хэш
`9a5bd2d0cf53d9ff` вместо `18d8af04a276288d`) — тогда сигнатуры функций не
совпадают и агент не находит `lua_resume`. Лечится `make symbols` (это
пересобирает `src/agent/luau_symbols.h` под текущий APK) и обновлением
сигнатур в агенте.

### E. Мелкое

- разбиение на части и для `loadstring` (сейчас длинный исходник внутри
  `loadstring` не влезает в 280 байт);
- `make test` — автотест агента (`tools/test_hook.c` устарел, писать заново);
- убрать `work/` в `.gitignore` (эталонная сборка Luau и образ клиента).

## 5. Правила игры

1. **Код клиента не трогать.** Любая правка его text приводит к тому, что
   клиент уходит примерно через 65 секунд после старта. Если правка
   неизбежна — она должна быть снята до проверки целостности.
2. **Состояние игры не ломать.** Скрипт исполняется на потоке игры; стек и
   верхушка потока восстанавливаются после выполнения.
3. **Проверять на живом клиенте.** `tools/selftest.py` (35 сниппетов),
   `tools/soak.py` (6 скриптов + простой), `tools/stress.py` (скрипты по
   кругу).
4. **Не коммитить непроверенное.** Каждый шаг проверяется на клиенте; в
   коммит попадает только то, что прошло selftest и soak.
5. **Таблицы адресов — производные.** При смене сборки клиента пересобираем
   `src/agent/luau_symbols.h` (`make symbols`) и карту опкодов
   (`tools/opcode_map.py`).
