# Wieen — дорожная карта

Документ отвечает на три вопроса: что уже работает, что мешает и в каком
порядке это чинить. Факты ниже проверены на живом клиенте; адреса и
наблюдения помечены как «проверено» или «гипотеза».

Дата: 2026-11-19. Ветка: `master`.

---

| приветствие в игре | **готово** — при выборе VM переживания агент сам зовёт `StarterGui:SetCore("SendNotification")` с заголовком `pwned by Wieen` и логотипом (`rbxassetid://113328400853000`), печатает `pwned by wieen! t.me/WieenExploit` в F9 (`tools/toast.luau`, §14) |

### Что работает прямо сейчас

```sh
python3 src/cli/wieen.py exec 'return typeof(game)'            # Instance
python3 src/cli/wieen.py exec 'return tostring(workspace.CurrentCamera.CFrame)'
python3 src/cli/wieen.py exec 'local f = loadstring("return 6*7") return f()'   # 42
python3 tools/selftest.py                                     # 35/35
python3 tools/soak.py 60                                      # 6/6, клиент жив
```

С правами скрипта (`WIEEN_INTHREAD=1`, права одалживаются по умолчанию):

```sh
python3 src/cli/wieen.py exec 'local h=workspace:GetDescendants()[38] h.WalkSpeed=100 return "ok"'
python3 src/cli/wieen.py exec 'local h=workspace:GetDescendants()[38] return tostring(h.WalkSpeed)'  # 100
```

### Ограничения

| ограничение | причина |
|---|---|
| `Instance.new` / запись свойств без `WIEEN_INTHREAD=1` | у нашего потока нет прав; лечится одолживанием маски окружения чанка |
| `workspace.CurrentCamera` | проверка контекста скрипта, маска её не открывает |
| `print` не появляется в консоли F9 внутри игры | консоль берёт сообщения контекста скрипта |
| штатный `loadstring` клиента всегда отказывает | та же причина (движок Roblox) |

`game.Players.LocalPlayer` и свойства `Player` теперь читаются: причина
отказов была не в контексте, а в том, что агент одалживал по смещению
`lua_State + 0x0c` маленькую маску из `caps.txt`. Там лежит счётчик, а не
маска; одолживание убрано, и Infinite Yield проходит до конца.

## 2. Три рубежа

### Рубеж 1. Исполнять код в потоке игры (рекомендуется)

Идея: выполнять наш скрипт **в том потоке, который вызывает `lua_resume`**.
Это поток скрипта игры, у него есть контекст целиком: все службы,
`Instance.new`, штатный `loadstring` клиента и консоль F9.

Не хватает одной вещи: функции вызова Luau из C (`lua_call` / `lua_pcall`)
**той же копии Luau**, что и у игры. Тогда:

1. агент грузит наш чанк в поток игры;
2. вызывает его через найденную функцию;
3. скрипт исполняется с контекстом игры.

Плюсы: код клиента не трогаем (переживает новые сборки), снимается сразу
четыре ограничения из таблицы выше. Минусы: нужна реверс-работа (поиск
функции) и аккуратная работа со стеком чужого потока.

### Рубеж 2. Уровень движка Roblox (C++)

Вызвать API движка так, чтобы он сам создал настоящий `LocalScript` с нашим
`Source`: движок выполнит его с полным контекстом. Требуется адрес API в
движке Roblox.

### Рубеж 3. Патч кода клиента + починка проверки целостности

Снимает все ограничения разом (и `loadstring`, и песочницу, и лимит 280
байт, и консоль), но клиент сверяет байты своего text и уходит примерно
через 65 секунд после старта. Значит, нужно найти эту проверку и подправить
ожидаемое значение. Хрупко: новая сборка клиента всё ломает.

**Рекомендация:** рубеж 1. Он единственный сохраняет главное свойство
проекта — инъекция в данные, без изменения кода клиента.

### Раскладка состояния Luau в клиенте

```
lua_State:  0x03 status   0x06 active   0x08 nCcalls   0x0a basecalls
            0x0c счётчик (не маска)   0x30 ci   0x38 global
            0x40 stack   0x48 top   0x50 base

global_State: cb.userthread +0x6a0   cb.preresume +0x678
              cb.postresume +0x650   счётчик +0x6b0
```

Поле `+0x0c` — не маска прав, а маленький счётчик клиента: во время
работы скриптов там появляются `0x3`, `0x6` и подобные значения. Настоящая
проверка доступа к инстансу — `0x22ea488`: она берёт `[[L+0x20]+0x80]`,
умножает (по И) на маску, на которую указывает `[env+0x70]` ближайшего
Lua-замыкания (или на маску по умолчанию `0x703eb90`), и кладёт результат
в общий checker `+0x30`. Поэтому одалживать `+0x0c` нельзя: это портит
счётчик и не даёт прав.

## 4. Ближайшие задачи

### A. Вызов Luau из C (рубеж 1) — **сделано, остались права**

Сделано (проверено на живом клиенте):

- `lua_pcall` в сборке нет: единственные два вызова `luaD_pcall` — это
  yieldable-обёртка (`0x31f868f`) и интерпретатор, поэтому прежние четыре
  кандидата были не тем, что искали;
- `lua_pcall` собран заново по upstream поверх `luaD_pcall` (`0x22e5729`) и
  `luaD_call` (`0x22e5b93`); `WIEEN_INTHREAD=1` исполняет скрипт в потоке
  игры;
- состояние игры после вызова совпадает с состоянием до него (проверяется
  `WIEEN_STATELOG=1`), скрипты с `wait()` автоматически уходят на обычный
  путь, `selftest` 35/35 в обоих режимах, `soak` и `stress` проходят.

Сделано: **права скрипта** (см. §12 в `docs/status.md`). Поток игры в
момент `preresume` имеет маску `0x1`, и подмена маски `+0x0c` ничего не
меняла. Оказалось, проверка спрашивает маску окружения чанка —
`[closure+0x18]+0x70` — и одолжить её (`WIEEN_ENVCAPS`) достаточно, чтобы
`Instance.new`, `Parent` и запись свойств на игровых инстансах проходили.
Не закрыто было чтение `Players.LocalPlayer` и `WalkSpeed` — оно то
проходило, то нет. Причина — гонка за общий checker прав
(`base+0x6f85d50`): его кэш `+0x30` переписывает любой скрипт игры. Сторож
(`WIEEN_GUARD`, по умолчанию включён) держит `+0x30 = ~0` и `+0x38 = 0` на
время вызова; после него `WalkSpeed` пишется 7/7, `Players` читается.
Подробности — §13 в `docs/status.md`. Осталось: `workspace.CurrentCamera`
и вызовы, которых в песочнице нет вообще.

### B. Снять лимит 280 байт — **сделано контейнером**

Чистый загрузчик искать не понадобилось. Обёртка `luau_load`
(`0x22e4b72`) на самом деле имеет два пути: блоб меньше `0x118` (280)
грузится как голый байткод, а блоб не меньше `0x118` считается
контейнером с подписью. Подпись версии 1 проверяет не саму полезную
нагрузку, а метку, сложенную с сидом, — поэтому её можно собрать на хосте
для любого байткода:

```
payload | 0x10 байт паддинга | 0x18 байт футера
pad[0x00..0x03] ^ pad[0x08..0x0b] == 0x946ac432
u16(footer[0x00]) == 0xc432, footer[2..3] == 0x6a, 0x01
u32(footer[0x10]) == 0x016ac432 ^ 0x74171870
```

Это делает `with_container()` в `tools/wieen_compile.cpp`. Пределы:
`MAX_MESSAGE` = 16 МиБ на кадр сокета, `kPartCap` = 4 МиБ на чанк; более
длинный скрипт по-прежнему режется на части. Проверено: Infinite Yield
(490 225 байт исходника, 605 731 байт байткода) приходит одним кадром,
`luau_load returned 0`, интерфейс строится (841 потомок `ScreenGui`).

### C. Разобрать конвенцию вызова компилятора клиента (`0x26d6400`)

Тогда `loadstring` работает без хоста, байткод сразу в формате клиента (без
нашего перевода опкодов — заодно снимается риск расхождения карты опкодов
на новых сборках).

### D. Перевод таблиц под новую сборку

Клиент иногда приходит новой сборкой (наблюдался хэш
`9a5bd2d0cf53d9ff` вместо `18d8af04a276288d`) — тогда сигнатуры функций не
совпадают и агент не находит `lua_resume`. Лечится `make symbols` (это
пересобирает `src/agent/luau_symbols.h` под текущий APK) и обновлением
сигнатур в агенте.

### E. Мелкое

- `make test` — автотест агента (`tools/test_hook.c` устарел, писать заново);
- убрать `work/` в `.gitignore` (эталонная сборка Luau и образ клиента).

## 5. Правила игры

1. **Код клиента не трогать.** Любая правка его text приводит к тому, что
   клиент уходит примерно через 65 секунд после старта. Если правка
   неизбежна — она должна быть снята до проверки целостности.
2. **Состояние игры не ломать.** Скрипт исполняется на потоке игры; стек и
   верхушка потока восстанавливаются после выполнения.
3. **Проверять на живом клиенте.** `tools/selftest.py` (35 сниппетов),
   `tools/soak.py` (6 скриптов + простой), `tools/stress.py` (скрипты по
   кругу).
4. **Не коммитить непроверенное.** Каждый шаг проверяется на клиенте; в
   коммит попадает только то, что прошло selftest и soak.
5. **Таблицы адресов — производные.** При смене сборки клиента пересобираем
   `src/agent/luau_symbols.h` (`make symbols`) и карту опкодов
   (`tools/opcode_map.py`).
