# Wieen — таск лист и статус

Дата: 2026-11-11. Ветка: `main`, последний коммит `3012d00` + незакоммиченные
изменения агента и инструментов.

Цель: **выполнять Luau-код внутри игры** (Roblox-клиента под Sober) с
доступом к `game`, `workspace` и API игровых скриптов.

---

## 1. Сводка

| Слой | Состояние |
|---|---|
| Внедрение в процесс клиента | **готово** — агент живёт внутри клиента, хук срабатывает |
| Перехват `lua_pcall` | **готово** — хук прозрачен, состояние игры не ломается |
| Канал до агента (UNIX-сокет) | **готово** — хост подключается, CLI работает |
| Компиляция Luau → байткод | **частично** — есть свой компилятор, но его байткод клиент не принимает |
| Выполнение кода в игре | **не готово** — главный оставшийся блокер (см. §3) |

## 2. Задачи

### Готово

- [x] **Репозиторий и структура проекта** — git, `src/agent`, `src/cli`, `tools`,
      `docs/`, `Makefile` (`make agent`, `make compile`, `make symbols`).
- [x] **Разбор архитектуры Sober** — клиент Roblox (Android x86-64, `libroblox.so`,
      116 МБ, стрипнут) грузится рантаймом из APK; собственный загрузчик
      `libloader.so`; `libbadcpu.so` — защита. Документы: `docs/reversing.md`,
      `docs/architecture.md`.
- [x] **Вектор внедрения** — `ld.so.preload` в рантайме flatpak доходит до
      процесса клиента (проверено: наша `.so` отображена в PID клиента).
      `LD_PRELOAD`/`LD_AUDIT` рантайм вырезает, но `ld.so.preload` — нет.
- [x] **Поиск API Luau в клиенте** — офлайн-восстановление функций из
      `.eh_frame` + сверка с эталонной сборкой Luau (`work/luau-src`).
      Ключевая находка: выравнивание по размеру функций даёт ложные
      совпадения, работает только связка «xref строки → функция → её
      вызывающий» (`tools/calls.py`, `tools/find_xref.py`).
- [x] **Адреса API в клиенте** (проверено по дизассемблированию и по
      сигнатурам вызовов):
      | функция | смещение | как найдена |
      |---|---|---|
      | `lua_pcall` | `0x22e9432` | вызывается скрипт-раннером Roblox (`0x42c94cc`) с `(L, 0, 0)` |
      | `luau_load` | `0x22e4b72` | вызывается тем же раннером; внутри — ссылка на загрузчик байткода |
      | `lua_tolstring` | `0x22e5f48` | вызывается на пути ошибки; проверяет тег `TT_STRING`, отдаёт `ptr+0x18` и длину по `+0x14` |
- [x] **Агент внутри клиента** (`src/agent/wieen_agent.c`):
      - ждёт появления образа клиента в своём адресном пространстве;
      - находит VM-функции по смещениям + проверке сигнатур (с откатом на
        ближайшее совпадение, если клиент обновился);
      - ставит хук на `lua_pcall` (13-байтный прологин, трамплин);
      - отдаёт UNIX-сокет `~/.var/app/org.vinegarhq.Sober/data/wieen/wieen.sock`;
      - выполняет полученный байткод в состоянии игры и возвращает результат.
- [x] **Свой компилятор на хосте** (`tools/wieen_compile.cpp` → `build/wieen-compile`),
      собирает Luau → байткод версии 13.
- [x] **CLI** (`src/cli/wieen.py`): `exec`, `run`, `repl`, `status`.
- [x] **Тест механики хука вне игры** (`tools/test_hook.c`) — хук прозрачен:
      функция возвращает ровно то же значение, что и без хука.
- [x] **Отладка падений** — найдено и исправлено три ошибки:
      1. `jmp rel32` не достаёт до mmap-области (клиент на 5 ГБ дальше) →
         абсолютный `mov r11, imm64; jmp r11`;
      2. обращение к глобальной переменной из mmap-страницы через RIP —
         та же проблема, заменено на абсолютный immediate;
      3. `48 83 ec 80` — байт 0x80 sign-extend'ится в −128, то есть `sub rsp,0x80`
         прибавлял 128 вместо вычитания → зависание; заменено на `48 81 ec 80 00 00 00`.

### В работе

- [ ] **Разбор состояния `lua_State` клиента** — хук срабатывает корректно
      (аргументы приходят как `(L, 0, 0)`, как и вызывает Roblox), но разбор
      полей по эталону Luau не подходит: `L+0x38` лежит `0x2`, `L+0x08` и
      `L+0x48` — указатели, `L+0x50` — ноль. Значит раскладка структуры в
      клиенте другая (или это состояние другого экземпляра VM). Нужно
      определить поля динамически, а не по константе.
- [ ] **Байткод не принимается VM клиента** — наш байткод (версия 13, флаги
      компилятора по умолчанию) роняет загрузчик клиента: клиент ждёт
      диапазон версий `[3..14]`, но формат/флаги отличаются от флагов
      сборки Roblox. Варианты: (а) найти в клиенте собственный `luau_compile`
      и компилировать в процессе; (б) повторить набор FFlag-флагов Roblox.
- [ ] **Долгоживущий тест** — клиент без логина живёт ~25 секунд, поэтому
      проверки надо делать сразу после старта (`tools/quick_test.py`).

### Не начато

- [ ] Поиск `luau_compile`/`luaL_loadstring` в клиенте (нужен для варианта (а)).
- [ ] Поддержка скриптов, которые уступают (`wait()`, `task.wait()`) —
  сейчас `lua_pcall` не может уступать.
- [ ] Режим «своё состояние»: создать `lua_State` внутри клиента, чтобы
  работать без открытой игры.
- [ ] Автозапуск: `wieen launch` с `--share=network`, чтобы сокет был виден
  с хоста без правки `ld.so.preload` вручную.
- [ ] Уборка: удалить пробы из `data/wieen/`, сбросить `ld.so.preload`
  рантайма, удалить `work/` из репозитория (или в `.gitignore`).
- [ ] Тесты: автотест `tools/test_hook.c` в `make test`.

## 3. Главный блокер

Клиентский VM и наш эталон Luau — **разные сборки**: у клиента другая
раскладка `lua_State` и другой формат байткода. Поэтому офлайн-восстановление
функций по эталону даёт правильные адреса только там, где адрес подтверждён
через строки и вызывающий код (это `lua_pcall`, `luau_load`, `lua_tolstring`).

Дальше нужны два шага:

1. **Динамическое определение раскладки `lua_State`.** В хуке мы знаем `L`
   и можем проверить структуру эмпирически: найти в состоянии два указателя
   на стек (база/топ) — они лежат в одном массиве, разница кратна 16 — и
   указатель на глобальное состояние. Это надёжнее констант.
2. **Свой компилятор в клиенте.** Либо найти `luau_compile` (через xref
   строк парсера → её вызывающий), либо повторить флаги Roblox.

Оба шага независимы: первый нужен, чтобы вообще иметь состояние, второй —
чтобы в него положить байткод.

## 4. Проверено / не проверено

**Проверено:**
- агент грузится в клиент и находит VM-функции по правильным смещениям;
- хук на `lua_pcall` ставится и срабатывает (сотни вызовов), клиент при этом
  не падает (состояние отбраковывается, если не похоже на `lua_State`);
- хост подключается к сокету агента, CLI отправляет байткод;
- механика хука прозрачна (отдельный тест).

**Не проверено:**
- выполнение кода внутри игры (нужен вход в аккаунт Roblox и заход на
  плейс — только там крутится игровой скрипт-раннер);
- приём байткода клиентским VM.

---

## 5. Порядок работ

1. Динамически определить раскладку `lua_State` в хуке (без констант).
2. Найти `luau_compile` в клиенте → компилировать в процессе, байткод
   гарантированно совпадает.
3. Прогнать `return 1+1` → затем `return typeof(game)` → затем
   `game.Players.LocalPlayer`.
4. Поддержка уступающих скриптов.
5. Уборка, автотесты, коммит.
