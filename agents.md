# agents.md — как работать в этом репозитории

Файл для ИИ-агентов (и для людей, которые впервые открывают проект).
Здесь — устройство, инварианты, команды и грабли, на которые уже наступали.

---

## 1. Что это

Wieen — инжектор Luau в клиент Roblox, запущенный под Sober (flatpak).
Агент грузится в процесс клиента, находит состояние Luau-VM и выполняет
в нём скрипты, с доступом к игровым объектам.

Репозиторий: <https://github.com/mansar1337/Wieen>. Ветка `master`.

Документация: `README.md` (как пользоваться), `docs/status.md` (что
исследовано), `docs/architecture.md` (устройство), `docs/reversing.md`
(реверс клиента), `roadmap.md` (дорожная карта).

## 2. Устройство

```
хост                                        агент (в процессе клиента)
────                                        ─────────────────────────
python3 src/cli/wieen.py exec '<lua>'  ──▶  UNIX-сокет
   tools/wieen_compile: исходник →          находим global_State (скан памяти)
   байткод + перевод опкодов                ставим свой обработчик в cb.preresume
                                            ждём, когда игра позовёт VM
                                            грузим байткод в поток, запускаем
   ◀─── результат (строка) ───────────────
```

Ключевое: **агент не меняет код клиента**. Хук — это указатель в
writable-памяти состояния VM (`cb.preresume`), который VM и так вызывает
перед каждым скриптом игры.

### Карта файлов

| путь | что это |
|---|---|
| `src/agent/wieen_agent.c` | агент: поиск образа и VM, хук, исполнение скриптов, права потока, `loadstring` |
| `src/agent/luau_symbols.h` | сгенерированные адреса функций Luau в клиенте (`make symbols`) |
| `src/cli/wieen.py` | хостовая CLI: `exec`, `run`, `repl`, `status`, `launch`, `install` |
| `tools/wieen_compile.cpp` | компилятор хоста: собирает байткод и переводит опкоды в формат клиента |
| `tools/opcode_map.py` / `.txt` / `.h` | таблица «upstream → слот клиента → wire-номер» |
| `tools/probe.luau` | проба VM: отличить VM игры от второго VM клиента |
| `tools/bin2h.py` | бинарник → C-заголовок (байткод пробы попадает в агента при сборке) |
| `tools/bytecode.py` | разбор блоба Luau (строки, константы, прототипы, опкоды) |

## 3. Сборка, запуск, проверка

```sh
make agent      # build/wieen_agent.so (+ байткод пробы)
make compile    # build/wieen-compile — компилятор хоста
make deploy     # положить агента туда, откуда его берёт Sober
make symbols    # пересобрать src/agent/luau_symbols.h под текущий APK
```

```sh
python3 src/cli/wieen.py launch     # запустить игру с агентом
python3 src/cli/wieen.py status     # агент жив?
python3 src/cli/wieen.py exec 'return typeof(game)'
python3 src/cli/wieen.py run file.luau
python3 src/cli/wieen.py repl       # интерактивно, выход: \!
```

Проверка перед коммитом (обязательно):

```sh
python3 tools/selftest.py           # ждём 0 из 35 упавших
python3 tools/soak.py 60            # ждём 6 из 6 и «client is still there»
```

Логи: `~/.var/app/org.vinegarhq.Sober/data/wieen/agent.log` (агент) и
`~/.var/app/org.vinegarhq.Sober/data/sober/sober_logs/latest.log` (клиент).

## 4. Инварианты (не нарушать)

1. **Код клиента не меняется.** Клиент сверяет байты своего text и
   уходит примерно через 65 секунд после старта. Проверено: запись тех же
   байт безопасна, любая другая — нет. Если правка кода неизбежна, её надо
   снять до проверки.
2. **Состояние игры возвращается как было.** Скрипт идёт на потоке игры;
   верхушка стека восстанавливается, лишний поток снимается.
3. **Поток игры не должен падать.** Ошибка в нашем скрипте не должна
   ломать скрипт игры.
4. **Байткод меньше 280 байт.** Roblox-обёртка `luau_load` берёт только
   такой. Всё, что больше, режется на части (`split_script` в
   `tools/wieen_compile.cpp`), части выполняются подряд в той же VM.
5. **Права потока копируются у потока игры** (маска в `+0x0c`): без этого
   недоступны даже `game` и `workspace.CurrentCamera`.
6. **Адреса — производные от сборки клиента.** Сменилась сборка — пересобрать
   `luau_symbols.h` и карту опкодов.

## 5. Диагностические флаги агента

Все включаются переменными окружения: `WIEEN_OFF=1 python3 src/cli/wieen.py launch`.

| флаг | что делает |
|---|---|
| `WIEEN_OFF=1` | агент не делает ничего (отделить его от поведения игры) |
| `WIEEN_SOCKET_LOG=1` | лог сокета |
| `WIEEN_SCAN=1` | все найденные совпадения сигнатур (пересборка таблиц) |
| `WIEEN_FAULTLOG=1` | подробный лог падений клиента |
| `WIEEN_CAPDIFF=1` | какие байты состояния отличаются у нашего потока и потока игры |
| `WIEEN_CTXSCAN=1` | поиск поля с контекстом скрипта в состоянии потока |
| `WIEEN_RICHCAPS=1` | объединение масок прав всех состояний VM |
| `WIEEN_COPYOFF=<смещение>` | скопировать в наш поток поле состояния по смещению |
| `WIEEN_INTHREAD=1` | выполнять скрипт в потоке игры (нужен `WIEEN_ALTPCALL`) |
| `WIEEN_ALTPCALL=<смещение>` | функция вызова Luau, которой пользоваться |
| `WIEEN_CLICOMP=<смещение>` | компилятор Luau внутри клиента |
| `WIEEN_ALTLOAD=<смещение>` | другой загрузчик байткода |
| `WIEEN_NOLOAD=1`, `WIEEN_NORESUME=1` | остановить исполнение на загрузке/запуске |
| `WIEEN_NOTHREAD=1`, `WIEEN_NOUSERTHREAD=1`, `WIEEN_LEAKTHREAD=1` | правила создания потока |
| `WIEEN_NOLOCKS=1`, `WIEEN_TAKEONLY=1`, `WIEEN_CLAIMNOREPLY=1` | варианты протокола (диагностика сети) |

## 6. Грабли (уже наступали)

- **Строка в C вида `"\x00compile:"` читается как `0x0C` + `"ompile:"`** —
  `\x00c` съедает ещё и `c`. Нужен разрыв: `"\x00" "compile:"`.
- **Скан памяти клиента гоняется с игровым потоком:** страница может исчезнуть
  между «увидели» и «прочитали», и клиент падает. Поэтому поиск состояния
  сделан через `sigsetjmp`/`siglongjmp`, а обработчики сигналов ставятся
  всегда (чужой сигнал уходит игре без изменений).
- **`make deploy` нельзя делать поверх живого клиента:** перезапись `.so`
  под映射ом роняет процесс с SIGBUS. Агент кладётся через `cp` во
  временный файл и `mv` (переименование) — старый процесс не трогается.
- **Клиент иногда приходит новой сборкой** (наблюдался хэш
  `9a5bd2d0cf53d9ff` вместо `18d8af04a276288d`): сигнатуры перестают
  совпадать, агент не находит `lua_resume`. Лечится `make symbols` и
  обновлением сигнатур в агенте.
- **В клиенте несколько копий Luau разных версий.** Функция из чужой
  копии не просто «не работает», а роняет клиент. Отсюда — перебор с
  перезапуском клиента на каждого кандидата.
- **У Roblox своя конвенция вызова**: у `luau_compile` исходник — третий
  аргумент, а не первый, как в upstream Luau.
- **В Roblox-обёртке `luau_load` есть проверка размера** (`cmp $0x118` =
  280) — это и есть причина отказа «bytecode corrupted» на больших
  байткодах.
- **Контекст скрипта игры — это не capability.** Права (`+0x0c`) копируются
  легко, а вот контекст (указатель в состоянии потока) — нет; он же
  проверяется в `loadstring` по флагу `+0x86d`.

## 7. Стиль

- Код, комментарии и документация — по-русски (как в существующих файлах).
- Комментарии объясняют **почему**, а не что; находки реверса пишем в
  `docs/status.md` с адресами и с тем, как проверялось.
- Коммит — одним делом, с описанием, что изменилось и как проверено.
- Не оставлять в коде отладочных режимов надолго: диагностика живёт под
  флагами (`WIEEN_*`), лишнее — удалять.
